# 豆奶画布自动更新

Windows 正式安装版从 `jiang11123/dbgzz` 的 GitHub Releases 获取稳定版本。启动时检查，运行期间每 15 分钟再检查；只有版本号更高的正式发布才会提示。修改本地代码、推送 Git 提交、创建草稿或预发布都不会让用户收到更新。

## 用户操作

- 发现新版后，左下角显示更新入口，Windows 显示通知；点击“下载并安装更新”查看下载进度。
- 下载后由 electron-updater 校验更新清单中的 SHA-512。校验失败不能安装，可以重试。
- 安装前沿用画布的保存流程。保存失败会暂停更新；豆包任务或下载未结束时也不启动安装。
- 覆盖安装后重新启动。沿用原 appId、安装路径和 `doubao-video-workspace` 用户数据目录。不得在升级过程中卸载并删除用户数据。
- 开发版和直接解压运行的版本禁用自动更新，提示安装正式安装版。已经分发且没有此功能的旧版需要先手动升级一次。

## 每次发布

1. 修改代码并完成该版本的验证；更新 `CHANGELOG.md`。
2. 在主工程提高版本号，例如 `npm version patch --no-git-tag-version`。首次带更新功能的安装版为 3.0.0，下一次发布应为 3.0.1 或更高。
3. 执行 `npm run package:win`。此命令重建后端、CLI、协议包、前端及 Electron 主程序，默认只生成本地安装包，不自动发布。
4. 核对 `release` 中的三个文件属于同一次构建：`dounai-canvas-Setup-版本-x64.exe`、对应的 `.exe.blockmap`、`latest.yml`。清单中的版本号、文件名、大小和 SHA-512 必须与安装包一致，不能发布后再修改 EXE。
5. 在原 GitHub 仓库创建同版本 Release 草稿，填写更新记录，上传这三个文件，完成检查后发布为正式版本。保留旧版本，不把测试版设为 Latest。
6. 用已安装的上一个版本验证：检查发现新版 → 下载 → 保存工作区 → 安装重启 → 确认版本号、账号、项目和素材仍可用。仅构建成功不能替代这一验收。

更新清单通过公开仓库分发，不在客户端放 GitHub Token。用户必须能连接 GitHub 才能检查和下载；离线时保留当前版本并允许重试。若以后改用国内服务器或对象存储，需改发布源并先给用户分发能识别新源的版本。

## 实现入口

- `src/main/app-update.ts`：检查、下载、状态转换与安装门禁。
- `src/main/main.ts`：正式安装版识别、主窗口 IPC 校验、系统通知、运行中任务保护。
- `src/preload/preload.ts` 的 `doubaoUpdater`：只暴露固定更新方法。
- 画布前端 `desktop-runtime.ts` / `desktop-update.ts`：接入 Electron，同时保留原有 Wails 接口与保存屏障。
- `electron-builder.json`：发布仓库、NSIS 安装包与更新元数据。

真正的跨版本覆盖安装和数据保留需要两个正式安装版本在独立环境验收；本地单元测试不代表这一环节已通过。
