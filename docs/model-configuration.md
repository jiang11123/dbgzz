# 模型配置与豆包节点

设置中的默认文本、图片、视频、音频和多模态模型使用用户配置的 API 渠道。豆包账号不会被加入默认模型，也不会被设为默认模型。

豆包节点在节点内选择账号，直接通过工作站本地网关调用豆包，不依赖默认 API 模型或 API 密钥。账号登录与可用额度以豆包页面为准。

## Agent 助手使用豆包账号

启动和账号变化时，工作站通过后端模型配置接口保证存在一个「豆包账号」渠道（`doubao-gateway`）：

- 包含文本模型 `doubao-account-N`（协议 `chat-completion`）、视频和图片模型（见下文），每个豆包账号各一项，请求走本地网关 `http://127.0.0.1:<端口>/v1`。
- 文本模型同时出现在 Agent 助手和文本节点的下拉里，视频、图片模型出现在对应节点的下拉里；都不写入模型列表和默认模型，所以不会出现在设置的默认模型中。
- 还没有配置任何文本模型（助手模型和默认文本模型都为空）时，助手默认选第一个豆包账号，可随时改选。已配置 API 文本模型时不会被抢占。
- 用户在助手里选的豆包账号会保留；该账号被删除后，助手选择自动清空。
- 渠道的地址、密钥或账号列表变化（例如网关换端口、轮换 API Key、增删账号）时会自动更新；读回的密钥为空或已脱敏时不据此反复改写。

## 节点里使用豆包账号（文本 / 图片 / 视频）

「豆包账号」渠道为每个账号登记 **3 个**模型：文本 `doubao-account-N`、视频 `doubao-video-account-N`（协议 `doubao-gateway-video`）、图片 `doubao-image-account-N`（协议 `doubao-gateway-image`），都走本地网关。账号再多，模型下拉里也只是每个账号一项。

- 原生文本 / 图片 / 视频节点的模型下拉里都会出现「豆包账号」分组，节点仍是普通节点，历史、重试、版本和结果取回沿用原生流程。
- 视频节点选中账号后，模型选择器旁边单独出现「豆包视频模型」下拉（Seedance 2.5 / 2.0 / 2.0 Fast / 2.0 Mini）；图片节点出现「豆包图片模型」下拉（Seedream 4.5 / 4.0 / 3.0）。选择保存在节点上，提交任务时经 `providerOptions.<协议>.video_model / image_model` 传给网关。
- 参数面板按豆包的能力显示：视频时长 4–30 秒、5 种比例、最多 4 张参考图；图片提供 1:1、4:3、3:4、16:9、9:16、3:2、2:3 共 7 种比例（2K 参考尺寸，实际像素由豆包决定）、最多 4 张参考图，一次一张，没有质量档位。
- 生成视频时节点会显示豆包的回复，可发送补充消息或点「确认生成」；点节点上的取消会同时取消豆包视频任务。
- 这些模型只出现在节点下拉，不进入设置里的默认模型。
- 豆包要求确认或需要人机验证时，后端任务保持进行中，由节点上的回复区展示。

限制：豆包网页对话不支持工具调用，所以选择豆包账号后 Agent 只能聊天和写内容，不能像 API 模型那样自动新建节点、连线等操作画布。

保存使用配置 revision 校验，冲突后重新读取再处理。此过程不修改账号、画布或节点数据；同步结果会写入日志。

## 其他

启动时仍会清理旧版本自动注入到默认模型的 `doubao-gateway` 引用，保留其他 API 渠道、凭据和默认选择。

旧版独立窗口中的“同步至 BeefTV”是显式导出到原生 BeefTV 的入口，启动与账号变更不会执行该导出。
