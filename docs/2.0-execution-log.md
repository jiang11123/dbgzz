### 5. P0 核心：账号池调度器

新增 `src/main/account-pool.ts`（约 200 行）+ `src/main/account-pool.test.ts`（8 个用例）。

**替换掉了最脏的一处硬编码**——旧 `pickAvailableAccount()` 会优先选"名字含旺仔"的账号：

```ts
// 旧：按账号名硬编码
const preferredAccounts = accounts.filter(a => a.isLoggedIn && a.name.includes('旺仔'));
```

新调度器提供五种健康状态：

| 状态 | 触发 | 恢复 |
|---|---|---|
| `healthy` | 默认 | — |
| `cooling` | 临时失败（网络/限流） | 指数退避 30s → 10min，到期自动恢复 |
| `quota_exhausted` | 页面提示额度用尽 | 次日 0 点自动恢复 |
| `captcha` | 命中 `710022004`/人机验证 | **永不自动恢复**，需人工处理 |
| `logged_out` | 会话失效 | **永不自动恢复**，需重新登录 |

调度在可用账号间**按权重随机**；验证码与掉线账号永不被选中。状态持久化到 `account-pool.json`，重启后额度与冷却不丢。

配套改动：

- `classifyDispatchFailure()`：把页面错误文本映射到失败类型（额度/验证码/掉线/临时）。
- 任务成功 → `pool.markOk()`；提交失败 → `pool.markFailure()` 并自动切换下一个账号。
- 额度/验证码命中后立即 `dispatchNextQueuedTask()`，不再让任务卡死。
- `GET /health` 返回账号池健康度快照；`GET /accounts` 返回每个账号的 health/available/dailyUsed/cooldown。
- 删除账号时同步 `pool.forgetAccount()`。
- 无可调度账号时，任务进入排队并在状态文本里显示各账号健康度与剩余冷却。
