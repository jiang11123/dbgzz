## 原任务实测

优先使用原生客户端中真实失败且保存了 provider ID、上游结果可取回的原任务，执行查询原任务与取回。若没有这种任务，可在当前下载器完整取回已有成功任务的原结果，并在最终新版原生画布显示首帧、实际播放及重开同一任务。这两条路径分别登记，不改任务失败状态、不破坏资源来制造恢复测试。不得通过新生成补齐没有原任务的模型。

实际下载与新版原生画布可分别执行，但各自必须有当前摘要、真实证据与同一任务/文件 hash。只重开旧文件不是当前下载器验收，确定性 fixture 也不是 native 实测。保存下载完成、资源保存、首帧观察与重开的真实时间；`firstFrameTiming=observation_upper_bound` 表示观察到首帧的最晚上界，不声称精确首帧时刻。完整解码并核对文件大小和 SHA256。

本版 `freshGeneration=false`，`paidSubmissionLimit/newPaidSubmissions/newBudgetCNY/newSpentCNY/newPendingCNY` 均为 0，`billingAttempts=[]`。这些字段只说明本版没有新增付费，原任务历史费用单独记录。历史 `budgetCNY/spentCNY/pendingCNY` 保持 null，`priorFinancialUncertainty` 保留 `status=unresolved`、`carriedFromVersion=v1.7.21`、`pendingCNY=null` 并引用 `docs/release-evidence/v1.7.21.json`；其记录继续保留 v1.7.20 的未决账务。

## 回执字段

- 顶层保存上述零新增费用、豁免与历史字段，以及 `liveModelCoverage=limited_to_existing_original_tasks`、`allModelsLiveTested=false`。另附实际模型、不可用原任务与未覆盖范围的说明。
- `ownerException`：`approvedBy=Ender`、验收选择原文、精确 scope、当前 `sourceDigest/evidence`。`releaseAuthorization`：完整发布指令原文、`scope=v1.7.22 only`、`additionalHumanReplyRequired=false`、当前 `sourceDigest/evidence`。
- `cases` 至少一条实际原任务取回：`method=native-original-task-retrieval`、`retrievalMethod=native-failed-task-recovery|current-downloader-original-task`、对应实际 `originalStatus=failed|succeeded`、`clientVersion=v1.7.22`、当前 `sourceDigest/executedSourceDigest/evidence`、`model/platform/resourceId`。`taskId/originalTaskId/reopenedTaskId` 相同，`providerRequestId/originalProviderRequestId` 相同；有网关任务时 `gatewayTaskId/originalGatewayTaskId` 相同，没有则两者 null。`freshSubmission=false/submissionCount=0/status=succeeded`。
- 每条 case 的 `downloaded/saved/canvasVerified/canvasFirstFrame/mediaDecoded/mediaOpened/playbackVerified/reopened/noDuplicateSubmission` 均为真实验证的 true；保存 `bytes/artifactSHA256`。`artifactIdentity` 使用 `existing-resource-sha256` 或 `same-task-repeat-readback`，`referenceSHA256` 与实际文件相同并引用核对证据。失败任务没有原本地文件时，可用同一上游原任务重复只读取回的 hash 核验。
- `downloadExecution`：`method=native|current-downloader`、当前 `sourceDigest/evidence`；真实失败任务恢复要求 native。`originalGeneration`：记录过旧生成来源时用 `status=recorded/commit/sourceDigest/evidence`；无法确定时必须 `status=unknown/commit=null/sourceDigest=null/evidence`，不从后来 review 或测试摘要推定来源。
- 每条 case 保存 `originalCreatedAt/retrievalStartedAt/downloadCompletedAt/savedAt/firstFrameObservedAt/reopenedAt`，取回发生于原任务创建之后、时间顺序真实；保存 `firstFrameTiming=observation_upper_bound`。
- `billingBefore/billingAfter` 均保存 `status=settled|refunded|unresolved` 和 `costCNY`，前后状态与金额相同；unknown 使用 unresolved/null，不能归零。`billingUnchanged` 保存 `status=passed/method=readonly-reconciliation`、当前 `sourceDigest/evidence`，须实际只读核账，不能从文件取回成功推定账务。
- `review`：真实 `result=approved/independent=true/reviewer`、当前 `sourceDigest/evidence`；`upgrade`：真实 `preservedData=true` 与当前 `sourceDigest/evidence`。
- `verification`：`allVideoProtocols/directAndBackupDelivery/signedURLRefresh/providerAuthIsolation/cancelAndStall/noDuplicateSubmission` 的 `method=test`，`localReleaseGate` 的 `method=local-script`，`ci` 的 `method=github-actions`；每项实际 `status=passed`、当前 `sourceDigest/evidence`。`allVideoProtocols.registeredProtocols/testedProtocols` 必须分别包含当前 `plugin-packages/*/manifest.json` 中全部 video provider ID，`handwrittenAndWorkflowDelivery=true`；证据覆盖故障、鉴权隔离、取消、原任务续签和无新提交。它只证明确定性协议行为，不代表每个模型真实生成成功。

验证脚本负责字段、版本与来源绑定；发布人和独立 reviewer 必须核对引用确实存在、测试范围真实，以及证据不包含凭据、签名素材 URL、余额或私有提示词。
