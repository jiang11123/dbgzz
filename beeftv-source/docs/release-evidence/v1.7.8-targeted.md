## 复现与修复

基线 `4ca2a65` 的真实 `CanvasNodeContent` 在浏览器载入包含 JSON 布尔 `generateAudio: true` 的视频节点时，缩略卡片正常，点击播放抛出 `metadata?.generateAudio?.trim is not a function`，播放器未挂载。

修复后的相同组件使用本地录制的 320×180 WebM，分别输入 `true`、`false`、`"true"`、`"false"`、对象和 null，点击播放后均出现解码画面，`videoWidth=320`、`currentTime>0.1`，页面错误数组为空。测试直接传入原始 JSON，未依赖事先规范化绕过错误。此证据是 Chromium 实际播放，不等同用户 Windows 设备验收。

规范化覆盖模型生成默认值、生成结果节点、项目打开的节点恢复、TapNow 导入和全局配置恢复。已观测 `hasAudio` 优先于生成设置；原有导演白膜静音规则保持。未知音频标记保持未知，不因类型异常崩溃。

## Windows 下载校验

Windows CI 暴露主线 `verifyDownloadedFile` 以 `os.Open` 的只读句柄调用 `Sync`。Windows `FlushFileBuffers` 要求可写句柄，导致完整包哈希通过后仍失败并删除部分文件。改为 `os.OpenFile(path, os.O_RDWR, 0)`，不创建、不截断、不修改权限，保留长度、SHA-256 与刷盘要求。新增合法包成功、等长篡改拒绝回归；本机 updater 全包通过，独立子 agent 代码复核通过。

经逐一读取标签，Windows v1.7.5、v1.7.6、v1.7.7 均含此错误。已安装的旧二进制不能由新清单修复，应退出应用后下载完整 v1.7.8 包升级并保留原数据目录。发布流水线的旧 EXE 替换/回滚测试采用预下载包，不能冒充旧版自动下载链验收。

Grok 增量复审 `20261005-224602-continue-1a665fe4` 实际读取下载、校验、重命名顺序及 Windows Go 系统调用实现，批准 `17cb471`，无剩余代码发现。后续仍以 Windows CI 运行结果作为该平台修复证据。
