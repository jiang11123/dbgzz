# 画布提交客户场景验证

本文件记录可复用的故障注入场景，不能代替真实 Go、真实供应商和实际产品页面验收。

历史反馈出现过两组不同输入描述：五张图片；一段视频加一张图片。诊断包没有点击起点及完整画布，不能把任一组合当成客户原画布，也不能据此认定唯一根因。以下图使用合成素材分别覆盖两组输入，再单独覆盖角色与配音。

## 自动化入口

```sh
cd web
bun test test/customer-generation-scenario.browser.test.ts
```

测试运行真实 React `useCanvasGeneration` / `useCanvasGenerationExecutor`、画布参考解析、模型规则、资源缓存、媒体元数据读取、任务 API 和画布恢复代码。只在 HTTP 传输处提供合成资源、角色和任务记录；没有复制生成、校验或恢复规则。

| 场景 | 故障注入 | 必须观察到 |
| --- | --- | --- |
| 五张图片 | 向真实缓存调度器排入 16 个任务并挂起活动下载 | 资源引用仍能提交；浏览器没有读取五张图片的二进制 |
| 一视频一图片 | 同上，视频元数据已完整 | 同上，并且提交保留一个视频与一个图片引用 |
| 角色主参考图 | 同上 | 角色版本解析保留；不下载角色图片再转 Base64 |
| 未播放配音 | 资源记录时长为零；返回有效 2.5 秒 PCM WAV | 浏览器真实读取出 2500ms 并传入任务；不是假造 duration |
| 准备期间取消 | 卡住角色详情响应，然后编辑画布并取消 | 零任务 POST，编辑和旧结果保留 |
| 准备期间编辑 | 卡住角色详情响应，改标题与输入，再放行 | 任务使用点击时的旧提示词；当前标题与输入保留 |
| 创建成功但丢响应 | HTTP 服务收到 POST 后丢掉浏览器响应，再刷新 | 固定操作标识已保存；仅 GET 按标识找回原任务；POST 总数仍为一 |
| 默认模型不支持输入 | 五图配单图协议能力 | 显示具体原因；零 POST、零素材下载，不自动换模型 |
| 同源 HTTP/1 下载占满 | 16 个缓存任务排队，同源媒体响应挂起 | 活动媒体下载不超过 4，任务保存与 POST 仍有连接可用 |

画布、角色、资源、任务标识均为测试合成值。没有客户原素材、真实凭据或付费请求。

## 交互浏览器入口

```sh
cd web
bun run test/fixtures/customer-generation-server.ts
```

服务仅监听 `127.0.0.1:4089`，打印四个场景 URL。让浏览器打开打印的 URL，点击「生成视频」即可驱动同一个真实 hook。

- URL 增加 `&block-cache`：占住真实缓存下载槽。
- 同时增加 `&same-origin-hang`：在 API 同源挂住下载，专门覆盖浏览器 HTTP/1 连接池饥饿；默认 blocker 转到独立媒体源以单独检查应用队列。
- 增加 `&hold-character`：角色详情等待，便于点击「准备期间修改画布」「取消准备」。
- 增加 `&lose-receipt`：任务已受理后延迟回执，让真实 Axios 超时；随后原 URL 增加 `&recover` 再打开。
- 增加 `&incompatible-model`：使用单图协议，验证五图明确拒绝。
- 当前页面同源 `/_scenario/state` 返回合成任务数、下载列表、操作查询和最后保存的图；`/_scenario/release` 放行下载或角色等待。

此页面是测试控制台，不是完整产品 UI；它证明真实 hook 在这些故障下的行为，不证明画布布局、用户点击目标或安装包正常。

## 真实产品与 Go 验收路线

由主验收者在整合后源码启动 Go 和 Vite，使用独立的 `.local/project-workbench-debug` 数据目录，避免读取或改写客户数据库。配置入口、媒体上传、画布保存、任务创建、结果取回均须走真实接口。

1. 在实际 `/canvas/:id` 页面通过上传创建五张合成图片，连接到同一个视频节点；输入与界面资源顺序一致的 `@图片1` 到 `@图片5`。另建一段合成视频加一张图片的组合，分别验证。
2. 为角色创建一个主参考图；另生成或导入有效音频，让旧资源记录的时长为零。确认不是仅使用浏览器已经缓存完整元数据的路径。
3. 对真实 UI 进行下载阻塞、角色响应等待、创建回执丢失和页面刷新。数据库中的任务数、操作标识及上游请求次数应共同验证一次提交；不能只数前端调用。
4. 真实付费只由主验收者执行，沿用用户授权的 58 元总预算；每次记录任务标识、供应商回执、实际结算及剩余预算。上次受理结果未知时先找回同一个任务。
5. 至少一个真实视频必须验证到：后端完成、素材已保存、画布可播放、刷新后仍能播放。上游完成或 HTTP 200 均不能单独算通过。

新建任务、同一任务取回和真正重新生成必须分别计数。本文件与合成测试本身不执行模型付费。

## 基线观察

基线为 `cfbe1ffd`。合成浏览器测试已观察到：五图、一视频一图片、角色图在缓存槽占满时未到任务 POST；普通视频入口没有操作标识；准备期间编辑的标题被视频写回覆盖。零时长音频真实浏览器探测、准备期间取消和不兼容模型明确拒绝通过。初版同源挂起同时暴露了 HTTP/1 连接池饥饿，因此现将应用下载队列与同源连接容量分别覆盖。合成视频元数据使用有效的 1280×720，避免把低于模型像素要求的输入误判为提交卡住。

这些是可达的本地复现，不足以证明历史客户故障只有一个原因。修复后必须用同一组场景重新运行；整合验收者另记录真实接口、真实 UI 及付费结果。

## 修复后回放

在整合 `8a5d576c`（提交标识与恢复）、`9d1c2cd6`（轻引用与配置解析）、`9a044ca2`（元数据 API 接入与缓存连接容量）后的前端源码上，运行以上同一测试入口：**9 pass、0 fail、59 个断言**。

已验证同源 HTTP/1 的 4 个下载挂起时仍可保存生成目标并创建任务；五图、一视频一图片及角色图均只提交资源引用；配音由浏览器读出 2500ms；取消不创建任务；等待中编辑与旧结果保留；丢回执刷新找回同一个任务且只有一次 POST；不兼容模型明确拒绝。

此结果是合成 HTTP 传输上的真实 React hook 验证。没有运行真实模型、没有花费生成预算，也没有把它计为真实 Go、安装包或供应商端完成证据。
