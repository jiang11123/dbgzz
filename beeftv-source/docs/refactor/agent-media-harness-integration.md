# BeefTV 创作助手：媒体与剪辑接入验收

日期：2026-10-08。基线：`ef65732`（`origin/main`）。本地分支：`codex/agent-media-harness-20261008`。这是本地实现与验证记录，不是上线回执。

## 用户得到什么

1. 助手先查看当前画布或用户已引用素材的概要，再看指定视频片段、听音频片段；检测黑场和音量时返回实测数据，不用模型猜测替代。
2. 用户可以在助手运行时补充文字要求。旧模型响应里的修改会被阻止，下一次官方模型请求读取新要求；已经执行的操作仍保留，可以撤销。
3. 助手可裁剪、排序、调节音量和字幕，保存时间线，并通过已有任务系统免费渲染本地视频预览。付费生成仍由现有确认入口开始。
4. 超时或模型响应失败显示“尚未完成”，保留回复、实际改动和撤销入口。“继续处理”填入输入框，用户确认要求后发送；不会暗中重复生成。
5. 主动停止也保留已显示的正文，只有读取到匹配本轮的最终回执后才以历史替换。历史暂时为空或读取失败时不抹掉正文。

## 接入方式

- 官方 pi SDK 与配套依赖钉选 `1.0.4`，保持官方会话、执行循环、压缩和重试。旧 JSONL v3 会话读取已验证。
- 官方 `AgentSession.steer()` 接收文字补充；产品用意图版本阻止旧响应继续写入，不另建 Agent 循环。
- `media.overview / inspect / check` 只打开归属验证通过、已就绪的资源。模型不能传任意 URL 或文件路径给 FFmpeg。素材版本是实际打开字节的 SHA256，后续检查必须匹配。
- `overview` 返回概况和真实 JPEG；`inspect` 返回有界 JPEG、MP4 或 WAV；`check` 返回黑场区间、平均和峰值音量。采样时间标记为请求的 seek 时间，不能当作逐帧精确 PTS。
- JPEG 使用官方 ImageContent；新 Durable 会话在官方工具历史中保存音视频短引用，原字节由受校验的本地媒体存储持有；宿主在实际 HTTP dispatch 前重新验证权限与版本。Gemini `openai-completions` 的 WAV 使用 `input_audio: {data: "<纯 base64>", format: "wav"}`，不得放入 `image_url`；这是 [Google 官方兼容协议](https://ai.google.dev/gemini-api/docs/openai#audio-understanding) 的音频格式。已有 MP4 编码路径保持不变，不能据音频协议修复宣称视频输入或模型理解质量通过。当前原生音视频入口仅开放给 Gemini `openai-completions` 连接；其他连接收到明确工具错误，仍可用画面与客观检测。实际协议接收、听音与看视频质量均须另做真实验收。
- 独立审查走 `media.review`，不改变主模型：默认 `mode: "video"` 保留 MP4 及原音轨；`mode: "audio"` 将已授权 WAV/MP3 素材的指定区间归一化为 WAV，通过 WAND `input_audio: {data, format: "wav"}` 检查。主模型（包括不能直接接收音频的 Opus）只收到工具的文字观察、来源、片段哈希、请求号与用量。两种模式都复用 `media.inspect` 的归属、版本与区间限制，保持 `replay: "unsafe"`，失败或中断不自动重发。[腾讯 WAND 接口合同](https://page.weixin.qq.com/smartpage/p/b1_AT4ACga-AMYijMx5JsNSiWGK6lP?p=QEm9pe) 列出 `input_audio` 的 mp3/wav 格式；协议合同及本地模拟服务测试不能证明真实供应商的听音准确度，该项仍需单独原生验收。
- `canvas.timeline.update` 复用既有编译与画布提交，验证素材/资源归属及 revision。规范化时保留可信 `assetId`，其他画布字段不变。
- `canvas.timeline.render` 在操作事务内复用既有本地任务服务。操作回执与任务一起提交，重复操作返回同一任务，回执失败时任务回滚；渲染任务的查询权限从后端成功回执构造。
- 撤销复用整轮前快照。既检查改动范围，也检查连续操作回执；用户后续修改或未声明字段变化时拒绝覆盖。

## 已获得的直接证据

- 实际 Node 宿主 + 官方 pi SDK + 本机模拟模型/操作端点：插话拒绝旧写入、下一请求读取补充、官方 JSONL 保存用户补充；真实 FFmpeg JPEG/WAV/MP4 进入实际 HTTP 且顺序正确；坏 SHA 素材没有发送。共 4 个场景通过，9 次本机请求，没有付费模型调用。
- 实际 SQLite 单连接：时间线保存、本地渲染任务接纳、幂等重放、操作回执失败回滚；实际 FFmpeg 产出可打开的约 1 秒视频。
- 真实 React hook 浏览器测试：正文到达后停止，历史失败/为空时保留正文，匹配最终回执后替换；发送及取消各 1 次，没有自动重发。
- 本地 DEV 助手面板已观察：中性未完成卡片、继续填入输入框、实际改动与撤销、运行中补充输入框及停止按钮。该面板是明确的视觉样例，不连接模型，不能充当完整桌面验收。
- 前端 TypeScript/生产构建、lint 和 62 个助手专项测试（含真实 hook 浏览器测试）通过。完整 pi 宿主 suite 97 项通过、0 失败（185.98 秒）。完整后端 `go test -p 1 ./... -timeout 15m` 通过，exit 0。真实后端预览与负例见 [本地渲染验收](agent-local-render-verification-20261008.md)。
- 初始广义 app 测试缺少本地生成的官方插件包；构建插件包后继续验收。90 秒整包累计时限过短。干净 HEAD 与候选的结算、单连接、生成矩阵分别通过（矩阵 40.212/38.949 秒，其中视频成功固定等待约 30 秒）。不把时限不足当作代码回归或测试通过。

## 当前约束与后续验收

- 单素材源文件上限 256 MiB；单次工具媒体上限 8 MiB；原生媒体请求上限 32 MiB；片段检查上限 15 秒，客观检测上限 5 分钟。大素材应切片。超限有明确原因，不能假装已经查看。
- 已验证路径为 Gemini OpenAI-compatible 原生媒体；没有自动更改用户主模型，没有把未核实的 `gemini3.8flash` 名称作为已上线模型。
- 官方 Skill 发现保持关闭。产品 Skill 已接入用户显式选择的已安装固定版本；不能把宿主机全部 Skill、AGENTS 或 shell 权限直接开放。
- 图片、视频、音频的粘贴、文件选择与拖入已接入真实上传和素材登记；附件可单独发送，保存用途与片段范围，并可再次引用。运行中可补充文字与媒体，权限仍固定为原回合权限。
- 新会话由官方 Pi Durable 驱动；观察连接断开不结束后台回合，重新连接可恢复。进程中断后仅在 Go 重新授权且符合安全重放规则时继续，未知付费写入不自动重放。见 [持久宿主验收](durable-host-verification-20261008.md)。
- 新 Durable 会话使用原生音视频短引用，避免 base64 影响官方文本估算；旧内嵌媒体历史保持可读。引用存储不能按普通临时缓存清理，长期历史淘汰仍需专门验收。见 [原生音视频短引用](native-part-store-verification-20261008.md)。
- 上述初始媒体接入验收没有公开发布；后续安装版与权限验收见 [Agent 权限与外部工具](agent-access-20261008.md)。正式发布与真实渠道回归应以各自回执为准。

原始媒体接入验收材料单独保留，包含 `media-steer-final.json`、宿主/后端/前端测试日志、只读审查回执及视觉样例截图。最终改动通过 `git diff --check`；本地测试服务器和浏览器样例页面已关闭。
