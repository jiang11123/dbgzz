## 规则

视频没有统一的 8000 或 32000 字符限制。默认值按协议和模型选取，用户已保存的能力配置或内置渠道目录中的明确值优先。`promptMaxChars: 0` 表示本地没有字符上限，由服务商继续校验，不能理解为服务商无限接收。系统不自动截断提示词。

字符数按 Unicode 码点统计；明确使用 UTF-16 的接口另存 `promptMaxUtf16Units`，前后端统一计数，常见表情占两个单位。Veo 的 token 上限不换算成字符数，交由上游校验。图片与文本模型的既有限制不受这次视频调整影响。

## 已核实的接口

### Runway

[Runway 官方 API](https://docs.dev.runwayml.com/api.md) 的同一生成接口会接入不同模型，按确切模型 ID 区分：

| 模型 ID | 上限 |
| --- | --- |
| `gen4.5`、`gen4_turbo`、`veo3.1`、`veo3.1_fast` | 1000 UTF-16 单位 |
| `happyhorse_1_0` | 2500 UTF-16 单位 |
| `seedance2`、`seedance2_fast`、`seedance2_mini` | 3500 字符 |
| `seedance2_5` | 15000 字符 |
| `hailuo3`、`h3_max` | 6000 字符 |
| 已列出的 Kling 2.5/3.0/O3、`grok_imagine_1_5`、`grok_imagine_1_5_lite` | schema max length 2500 |
| `wan3`、`wan3_prime` | schema max length 20000 |
| `gemini_omni_flash`、`gemini_omni_flash_1.1` | schema max length 4000 |

未明确写 UTF-16 的 schema 长度按 Unicode 字符校验，不额外推断 token 上限。未知或新增 ID 不通过前缀猜测限制。

## 未核实与升级

Agnes 文档未公开字符硬上限；Kling、Hunyuan、Baidu、Vidu 插件当前端点与找到的官方文档不一致，无法套用其他端点的上限。动态 fal、Replicate 和自定义工作流也不能从模型显示名确定合同。这些无配置默认值为 0，不沿用通用 8000，也不宣称所有供应商路径均已验收。MiniMax 插件走 V2，仅匹配 `MiniMax-H3` / `MiniMax-H3-Max` 的 7000，不把 V1 Hailuo2 的 2000 套到该协议。

旧配置中的 8000 可能来自历史默认，也可能是用户主动设置，不能仅凭数值猜测并覆盖。内置 BeefAPI 渠道升级到支持 0 的客户端后刷新模型目录；自定义渠道在模型能力设置中选择“恢复默认限制”，或填写该渠道明确要求的数值。目录刷新沿用现有整体更新策略；本地默认合并保留已保存的自定义值。

旧客户端可能拒绝包含 0 的新目录能力并沿用缓存，服务端更新不能替代客户端升级。真实生成成功只证明该请求被执行；允许更长提示词不保证人物对应、台词、构图等全部遵循。
