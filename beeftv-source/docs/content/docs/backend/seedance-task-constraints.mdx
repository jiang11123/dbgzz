## Seedance 2.5 的任务模式

依据[火山官方 2.5 指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)，模式会决定哪些输出参数可以自定义：

| 模式 | 素材角色 | 比例 | 时长 |
| --- | --- | --- | --- |
| 文本或语义参考生成 | `reference_image/video/audio` | 可设置 | 可设置 |
| 首帧、首尾帧 | `first_frame/last_frame` | `adaptive`，跟随首帧 | 可设置 |
| 编辑视频 | 参考视频及其他参考素材 | `adaptive` | `-1`，跟随原视频 |
| 延长视频 | 参考视频及其他参考素材 | `adaptive` | 可设置 |

2.0 与 2.5 的模式约束不同，不应把 2.5 的规则全部套到 2.0。模型别名（包括 `seedance-2.5-official`）也需要命中对应版本。

BeefTV 保留明确的素材角色和已选模式。2.5 首帧任务显式发送自适应比例；不依赖省略参数后的供应商默认值，也不将自适应改成横屏比例。明确的编辑、延长请求使用上表参数；普通参考视频不会仅因含有视频就自动改成编辑或延长。界面只显示当前渠道已声明支持的模式。

模型可能依据提示词判断编辑、延长意图。客户端不通过关键词猜测并改写用户请求；若模型判定的任务类型与所选参数不兼容，会提示调整比例、时长或任务模式。画布专业模式可明确选择参考生成或首尾帧，具体能力以当前渠道为准。

## 三层限制分别核对

### 提示词长度与素材引用

Seedance 原生 API 未公布字符硬上限，BeefTV 和 BeefAPI 目录不再为它人为设置 8000 或 32000 字符上限。ModelArk MCP 工具的 32000 只是共享输入字段范围，不能代替具体模型合同。已明确保存的渠道限制继续生效；内置渠道需要升级客户端并刷新模型目录，自定义渠道可在能力设置中恢复默认限制。各接口的数值和计数单位见[视频提示词长度](/docs/backend/video-prompt-limits)。放行长文不等于模型会遵循全部指令。

“一键引用全文”只关联素材名称和图片编号，不改写人数、时长、台词数量或素材表中的独立数字。图片别名按图片自身编号解析，不按图片、音频混排后的货架位置解析；输入货架序号并按 Tab 的显式补全仍可使用。

图片、视频生成会在提交前检查明确的 `IMAGE N` 素材表：若表中的已知素材引用与最终上传槽位不一致，会提示先统一编号，不会自动选择一套解释并付费生成。Markdown 反引号、引号和表格里的数字引用与普通引用一样解析。文本任务和未绑定的普通表格不受该检查影响。编号一致也不能排除模型混用人像图里的服装；人脸、服装、站位和说话人应分别说明，并检查实际成片。

画布新插入的引用保存节点或素材 ID，显示名称、拖动素材和重新打开画布不会将其重新解释成另一份素材。普通视频提交保留这些绑定，直到最终模型、操作和素材列表确定后，才在提交副本中生成接口编号；保存的提示词不被覆盖。

Seedance 全能参考对这些明确绑定的媒体按首次引用排列，接口编号直接来自最终列表。旧的 `@图片N` 等位置引用继续保留原槽位；混合新旧引用时不自动调序，不改写用户自由文本中的 IMAGE 表、序数或剧情。首尾帧、固定工作流输入口和其他模型继续按各自位置合同转换引用。这个处理保证引用对应关系，不保证模型遵循长文中的全部要求。

在 Ark 原生或 BeefAPI/OpenAI Videos 接入的 Seedance 全能参考模式引用角色卡时，生成请求会注明角色名称、角色编号对应的最终图片编号和音频编号。补充视图按所属角色归组，共用音色按实际音频槽位绑定，不假定一张图或一条音频等于一个角色。模式即使不追加完整角色设定，也保留这段身份对应。角色绑定在最终素材列表确定后生成，不通过替换旧数字推算。配音、图片、首尾帧、H3 排序和自定义工作流不追加这段 Seedance 绑定。这修复的是请求缺少角色对应信息的问题，不能代替对具体成片的人物、动作和台词验收。

失败视频的“重试”复用后端保存的原任务请求，素材和提示词不随当前画布变化而更换；编辑后再次生成按新输入提交。已接收或完成的原任务继续查询、取回，不重新提交。

依据[官方提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-0-prompt-guide?lang=zh)，多张图对应同一人物时应明确绑定，并保持称呼一致。人脸图和服装图用途应写清，避免把多视图拼图中的人物解释为多个主体。接口编号从最终同类素材列表计算，也可参考 [ComfyUI 的编号实现](https://github.com/Comfy-Org/ComfyUI/blob/46aad33e4d4c0696582611bf450dd93742fa9090/comfy_api_nodes/nodes_bytedance.py#L244)；该实现不能作为模型生成质量保证。

### WhatsToken 线路的画幅兼容

BeefAPI 渠道层对 WhatsToken 的 `seedance-2.5-official` 首帧请求读取图片尺寸，将 `adaptive` 转成同一固定比例。仅接受能够精确对应 1:1、4:3、3:4、9:16、16:9、21:9 的图片；不裁剪、不按最近比例取整。其他渠道及火山直连保留原生合同。无法读取尺寸或无法保持比例时，客户端提示重新上传、调整首帧或更换模型。

BeefTV 的 2.5 首帧设置显示“随首帧”，编辑/延长显示“随原视频”；编辑时长也随原视频。切回参考生成后恢复自由设置，保留用户原先选择。

已知 WhatsToken 2.0 标准版和 2.5 带参考视频时可能忽略固定比例。内置企业渠道及直接配置的 WhatsToken 渠道对此在画布实际提交前提示风险，由用户选择返回调整或继续付费生成；Fast、Mini、普通文生和火山直连不触发该提示。该提示是临时的已知线路提示，不代表网关的动态路由能力接口；线路修复或切换后应复验并更新提示范围。

任务结果按提交时的参数与读到的实际视频尺寸比较，明显不符时保留原片并在结果卡提示；忽略小幅编码尺寸偏差。没有媒体尺寸时不猜测结果。提示不会自动发起新任务、裁剪、修改账单或承诺退款。

内置 BeefAPI 的 Seedance 2.0/2.5 通过 Videos API 提交全能参考。配置加载会修复旧版本自动写入的“视频、音频参考数量为 0”配置，并保留无关自定义限制。模型目录导入、重新连接和重启后均应保留参考能力；不要仅验证手工构造的能力对象。用户自定义渠道的明确限制仍按其配置执行。

本地素材最终是否可发送还取决于接入渠道的媒体合同。内置 BeefAPI 的 Seedance 由本机后端把参考图片、视频、音频上传为短期 HTTPS 链接后再提交 `/v1/videos`；工作区已有公开访问地址时也走这条路径。单文件仍按模型规格校验，整次 JSON 上限仍是 64MiB。不会自动裁剪或压缩。WhatsToken 官方线路需要 HTTPS 素材地址；界面允许选中模型不等于上游已完成素材校验。直连方舟和用户自定义渠道仍按其原传输方式发送。

1. **模型能力**：模型版本、任务模式、素材种类、数量、单段和总时长、尺寸、分辨率。
2. **接入合同**：方舟原生 API、BeefAPI `/v1/videos`、第三方中转的字段与默认值分别核对，不能互相代替。
3. **内容审核**：输入、输出及图片、音频、视频的审核结果不等同参数错误。修改尺寸无法解决版权审核失败。

素材数值限制参考[官方 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)和具体渠道的能力配置，不把提示词指南中的效果建议当成硬限制。

## 异步报错与排查

[官方任务说明](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)指出，部分 2.5 任务要到消费阶段才返回参数错误。任务 ID 只证明创建成功，不证明所有参数均已通过模型校验。

遇到 `InvalidParameter.TaskTypeConstraint` 时，核对最终发送的 `ratio`、`duration` 和每个素材的 `role`，包括省略字段。`fail_to_fetch_task` 等外层包装不能覆盖内部的具体参数原因。任务列表、画布及重启后的记录应保留同样的调整建议和排查编号。

若发送体没有比例却收到比例错误，应继续核对中转的默认值和转换结果；不能仅凭这条报错判定客户端、网关或供应商中的某一方承担全部原因。失败任务不自动原样重提。

显式选择全能参考时，Seedance 2.5 请求传入
`omni_reference_task_type=reference`；视频编辑和延长分别传入 `edit` / `extend`。
企业 Videos 请求使用 metadata，原生和兼容插件使用对应顶层字段；2.0 与未指定模式保留原行为。
供应商 `model_temporarily_unavailable` 归类为模型暂不可用，不能解释成用户余额不足。

## 参考视频像素与元数据校验

视频时长已知不等于尺寸已知。前端会为本地视频和受管资源补读宽高；后端对本地资源及内嵌 MP4/MOV 读取真实容器尺寸，覆盖旧元数据。尺寸仍无法读取时停止提交，提示重新导入；`asset://` 是供应商持有的素材，保留标识交由供应商校验。

像素限制针对每个参考视频的宽×高，与输出分辨率、文件体积、参考图片规则相互独立。错误提示应保留素材序号、实际尺寸、总像素及允许范围，并在任务历史再次读取时保留调整方法。不会自动放大、裁剪或重试用户素材。

文档核对（2026-09-29）：

|来源|适用范围|处理|
|---|---|---|
|[火山真人素材库](https://docs.volcengine.com/docs/ark/upload-real-person-portrait-assets?lang=zh)|视频总像素 407696–8295044，图片另列边长与宽高比|不能把视频像素规则套到图片|
|[WhatsToken 原生接口](https://www.whatstoken.ai/api/v1/plugins/docs-api/public/docs/11?lang=zh)|原生任务提交和查询接口|维持原生协议，不套兼容接口的参数枚举|
|[WhatsToken 素材库](https://www.whatstoken.ai/api/v1/plugins/docs-api/public/docs/27?lang=zh)|素材管理接口，引用火山素材库|已知 BeefAPI/WhatsToken 地址以及原生 Ark Seedance 2.x 的旧默认视频像素下限对齐 407696；其他模型与用户自定义限制不迁移|
|[WhatsToken 兼容视频接口](https://www.whatstoken.ai/api/v1/plugins/docs-api/public/docs/47?lang=zh)|兼容路由的 images/videos/role/type 等字段|不把其 5/10 秒简化表视作原生 Seedance 全部能力|

已覆盖数量、文件大小、单段及合计时长、边长、宽高比、视频总像素与角色参数。帧率从视频轨的采样时间读取，支持普通、分片及混合 MP4；不会拿音轨时长代算。直连 WhatsToken 与原生 Ark Seedance 2.x 在本地校验 24–60 FPS；企业渠道由网关根据实际线路校验。23.976 低于该下限。用户自定义渠道的明确限制仍按其配置执行。

MP4/MOV 是容器格式，不是完整编码白名单。编码标识从视频轨读取，未被解析器识别的编码不直接判为模型不支持。上游明确拒绝编码时，会提示重新导出素材；只修改文件后缀无效。

不透明素材仍须区分权限与有效性：[火山 GetAsset](https://docs.volcengine.com/docs/ark/get-asset-api?lang=zh) 需要 IAM 签名凭据，普通模型 API Key 不能替代；WhatsToken 仅允许素材所属账号查询。查询不到属性不等于素材损坏，也不能使用共享渠道凭据跨用户读取原文件。素材处理中、无权限和编码不支持分别提示处理方法。

素材库允许入库不等于所有模型都能使用该素材。已知全能参考输出比例偏差与输入校验是不同问题。
