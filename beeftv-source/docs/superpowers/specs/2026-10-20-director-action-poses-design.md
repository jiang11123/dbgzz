# 导演台动作预设优化设计

## 目标

让导演台中的跑步、蹲下、单膝跪、双膝跪、鞠躬、思考、格斗、踢球、伸手、抱臂和看手机这十一项预设，在标准男性、标准女性及程序化角色上呈现可辨识、稳定且符合接触关系的动作。通过本机 `/Applications/BeefTV.app` 验收。

## 现状与根因

姿势选择位于 `canvas-director-workbench.tsx`，目前每项只映射到 `DirectorPose`。`directorPoseBoneDeltas` 在 `director-scene.ts` 中为姿势返回局部四元数，`applyDirectorBoneTracks` 将其叠加到骨骼静置旋转；程序化角色则在 `director-procedural-pose.ts` 中用相同增量计算关节位置。

这套表示没有骨盆平移、末端目标或接触约束。它能表达部分静态摆臂和屈膝，却无法保证蹲姿重心下降、膝盖或足底落地、手触及下巴/手机/对侧手臂，也无法解决不同模型的局部骨骼轴向差异。跑步目前仅为单帧骨骼旋转，没有周期相位和交替支撑。截图中的思考姿势未形成明确的手与下巴关系；辅助骨架线与角色网格也有可见偏移，需要针对实际 Quaternius 模型复核。

## 设计

### 1. 语义化姿势定义

新增纯数据姿势定义层，姿势定义包含：

- 兼容现有 `DirectorPose` 的标识与基础骨骼姿态；
- 骨盆平移和躯干补偿；
- 可选的手腕、脚踝、膝盖目标点，使用身高归一化的角色局部坐标；
- 支撑点/接触点声明和目标方向；
- 对跑步等循环动作使用的周期时长与关键相位。

姿势标识与场景保存结构保持兼容；姿势定义作为代码资源，不把派生目标重复写进场景数据。`DirectorPose` 现有值和 Inspector 的预设按钮保持不变。

### 2. 静置骨架标定与 IK

基于实际映射到的骨骼和静置骨架，读取肢段长度及父子关系。姿势增量在角色局部坐标中表达，并以每个骨架自己的静置旋转为基准。十一项改进姿势由标定/方向求解处理左右侧和骨架局部轴；其他旧姿势保留既有站立基础旋转兼容逻辑。

为肩—肘—腕、髋—膝—踝链实现两段式 IK：根据起点、末端目标、两段骨长和极向量求中间关节，再转换为各自骨骼的局部旋转。求解不得改变模型对象变换；骨盆高度由姿势定义控制，支撑足/膝目标保持在地面坐标附近。缺少必要骨骼或肢段长度无效时，对该链保留安全的站立基础姿态，不产生 NaN 或破坏模型。

程序化角色继续使用同一套语义目标和骨长比例。其关节求解结果同时驱动实体几何和编辑器骨架辅助线，避免视觉与控制骨架走不同路径。

### 3. 十一项姿势的动作语义

| 姿势 | 定义与约束 |
| --- | --- |
| 跑步 | 以时间轴播放时间驱动循环步态；至少有左右交替支撑/摆动相、屈膝、反向摆臂、轻微前倾和周期性骨盆起伏。循环首尾连续。静止时间点仍呈现可辨认的跑步相位。 |
| 蹲下 | 双脚分开并保持足底接地；骨盆下降，髋膝协同弯曲，躯干适度前倾以维持重心。 |
| 单膝跪 | 固定一侧膝盖接地，另一脚稳定落地；骨盆下降，支撑脚和落地膝位置明确，姿态呈现清楚的前后错位。 |
| 双膝跪 | 双膝接地，胫骨/脚背方向合理，骨盆降至脚跟附近，躯干保持平衡。 |
| 鞠躬 | 由髋与脊柱分段前倾，骨盆保持稳定，颈部/头部补偿使头颈连续且视线自然。 |
| 思考 | 一侧手腕到达下巴/面颊目标，肘部有支撑形态；头部与视线朝向手或前下方，另一侧手臂自然承担平衡。 |
| 格斗 | 双手进入护脸区域，肘部收拢；双脚错步、膝微屈、躯干轻度侧转，重心落在支撑区域。 |
| 踢球 | 支撑脚留在地面；踢球腿定格在清晰的向前踢击/随摆阶段，髋膝位置可辨，骨盆与躯干向反方向补偿。 |
| 伸手 | 手腕到达明确的前向目标，肘部轻弯，肩胛/躯干少量配合；左右手目标可由同一姿势镜像。 |
| 抱臂 | 左右手腕到达对侧上臂附近，肘部错开，前臂交叉顺序稳定，避免手臂穿过躯干。 |
| 看手机 | 双手腕汇聚至同一手机目标区域，手掌朝向目标，头部俯视并使视线对准双手之间。手机可暂不生成独立道具，但两手间距与朝向必须一致。 |

### 4. 骨架辅助线

保留当前工作区中已有的 `DirectorSkeletonHelper` 调整，不改写未提交内容。验证其辅助线端点与标准男女 Quaternius 模型对应骨骼在以下状态下重合：静置、姿势应用、骨盆/肢体 IK、角色移动/旋转/缩放。若实测发现现有 helper 仍偏移，再以单独的失败用例定位和修复。

## 范围

- 包含十一项姿势定义、骨架标定、两段 IK、跑步相位评估、程序化角色共享语义目标，以及相关回归验证。
- 包含标准男性/女性 Quaternius 角色和内置程序化角色。自定义 GLB 只在其映射骨架具备必要链条时使用 IK，缺骨骼时安全回退。
- 不新增姿势按钮，不重做 Inspector 视觉，不重建角色模型，不引入新的运行时依赖。
- 不改动工作区内既有节点布局、相机属性、主题样式等无关未提交改动。

## 验收标准

1. 十一项姿势各自通过可重复的目标空间断言：手/下巴与手/手机/对侧手臂距离在定义容差内；蹲姿和跪姿接触点落在地面容差内；支撑脚无明显离地或穿地。
2. 男性、女性真实 GLB 的姿势端点都落在目标容差内；其静置骨骼线框与网格骨骼端点一致。运行时无 NaN/Infinity。
3. 跑步的左右支撑交替、摆动高度和一个完整周期的首尾连续性通过逻辑验证；时间轴暂停时结果稳定，播放时相位连续。
4. Inspector 继续展示现有二十个姿势按钮，切换姿势会清除旧骨骼覆盖并正确更新姿势；手动骨骼覆盖、关键帧和动作片段现有优先级不回退。
5. 相关前端类型检查、姿势/骨架定向测试和本地发布检查通过。
6. 按项目流程更新 `/Applications/BeefTV.app` 到本次源码版本，并在该安装版中实际逐项检查十一类姿势、骨架线框和跑步播放；向用户汇报版本、操作路径、结果及限制供其本地验收。

## 已知约束

- 角色局部坐标按模型标准化后的身高和骨骼长度归一化；不同身材使用相同的语义目标比例，IK 以实际段长夹取不可达目标。
- 自定义骨架命名/拓扑可能无法完成全链 IK；缺失链保留站立基础姿态，无法保证自定义模型也完成全部动作。
- 验收需要可视化检查，数值断言不能代替安装版中的人物轮廓与接触观感检查。
