# BeefTV 导演台画布阶段设计（LibTV 交互对齐）

## 目标与边界

最终目标是让 BeefTV 导演台达到用户可感知的 LibTV 导演台视觉与交互高保真；本规格只覆盖第一阶段：画布导演节点、独立场景描述输入、打开工作台、关闭后封面回写。后续工作台布局、场景树、属性面板、角色姿态、机位、时间轴、全景图、截图及 AI 导入分别设计与验收，不在本阶段假装已实现。

保留 BeefTV 现有 `DirectorScene`、3D 渲染、项目存储和资源服务作为内核。参考的是产品可见的 UI 与交互，不接入 LibTV 私有接口、账户数据或其素材。本阶段不调用 Seedance、付费生成服务或任何新的远端 3D 生成接口。

## 已核对的参考与现状

- 在 1440×900 参考画布中，LibTV 导演节点有卡片外标题、近正方形封面卡片、悬停出现的“打开导演台”，下方独立的场景描述编辑区。关闭工作台后，卡片自动变为最新场景截图。
- BeefTV 当前 `CanvasDirectorNodePanel` 在卡片内展示标题、镜头名、3D 徽章、统计；封面依赖显式 `applyDirectorOutput`，该路径还会创建独立图片节点。现有输入元数据 `composerContent` 可以复用，但不能把导演场景输入交给普通视频生成处理器。
- 当前创建入口要求选择模板。第一阶段保留模板选择入口和已有项目的兼容读取；不以改动模板默认值来“模拟”参考空态。新节点的布局与状态需对所选模板和旧项目一致生效。

## 用户流程与状态

1. 用户沿用现有入口创建导演节点。节点标题位于预览卡片外；卡片下方有独立“描述想要搭建的场景”输入区。标题、卡片、输入区在画布缩放下作为同一节点移动和保存。
2. 无截图时卡片呈诚实空态，主要操作为“打开导演台”；已有有效截图时静态展示截图，鼠标悬停或键盘聚焦时出现同一操作。卡片始终可被键盘操作，焦点可见。加载、截图失败、图片加载失败均不得表现为无解释黑块。
3. 点击打开后进入现有 3D 工作台，保留当前场景编辑能力；关闭时遵循现有保存检查与“保存失败是否仍离开”的决定流程。在仍持有有效 3D 视口时采集本地截图，场景保存成功后将截图作为**同一导演节点**的封面；随后才卸载工作台。普通关闭不额外创建图片/视频节点，也不提交生成任务。
4. 用户可在节点输入区编辑场景描述；输入持续保存在该导演节点的 `composerContent`，并在重新打开、项目重载后恢复。输入内容不自动发起视频生成。若未来加入“生成场景”操作，必须独立实现并有明确状态；本阶段不放置可误导用户的可点击发送按钮。
5. 如果场景没有可见变更且已有有效封面，关闭时不重复截图和资源写入；场景变化才更新封面。截图或写入失败时仍保存场景、保留旧封面并显示可重试的非阻塞提示。首次失败则回到空态，而非黑框。

## 数据与异步一致性

- 节点仍使用 `workflowKind: "shot"`、`directorSceneId`、`directorShotId`；封面使用现有受控资源体系及可持久化的元数据引用，不把临时 blob URL 或机器绝对路径写入项目。
- 自动封面是节点自身的展示数据，不加入 `referenceAssetNodeIds`、不建立画布连线，也不复用会产生额外图片/白膜节点的 `applyDirectorOutput`；显式“应用构图/输出”仍走原路径，不改变既有输出合同。
- 截图提交携带项目 ID、节点 ID、场景 ID、镜头 ID 和场景修订标识。异步存储完成前后都核对当前权威项目/节点/场景；节点被删除、项目切换或更新截图任务已 supersede 时不得回写旧结果。
- 场景保存与封面更新分离。截图失败不能回滚成功的场景编辑；重复关闭不得产生无界的并发上传。复用现有资源去重/清理策略，不静默删除旧资源。
- 工作台 `viewportRef.capture("beauty")` 只能在卸载前调用；不得把截图放到现有 `onClose={() => setDirectorNodeId(null)}` 之后。现有 `prepareClose` 若阻止退出，工作台必须保持打开；用户明确选择“仍然离开”时，即使远端保存失败，也不得把未确认持久化的场景截图伪装成已保存封面。
- 导演输入事件要阻断画布拖拽、缩放和快捷键的冲突；节点移动和键盘操作仍可正常使用。输入只写本节点的场景描述，不能进入 `videoEditOperation: "text_to_video"` 的生成提交路径。

## 视觉与交互验收

- 以同一 1440×900 视口、相同画布缩放和主题，对照已采集的 LibTV `canvas-initial.png`、`canvas-node-stable.png`、`node-hover-settled.png`。优先对齐标题位置、封面纵横比、留白、暗色、边框、文案和悬停层级；尊重 BeefTV 全局 token，不硬编码只适配一张截图的坐标。
- 空态、已有封面、悬停、键盘聚焦、截图加载/失败、工作台关闭后更新、项目重载均有可重复截图或自动化断言。
- 当预览原图不是正方形时完整显示并保持纵横比，周边填充与参考一致，不拉伸主体。
- 在窄画布视口和 125%/75% 缩放下，输入区、节点连接锚点、拖拽区域不重叠或错位。输入区聚焦时不触发节点拖动。
- 本阶段只声明“画布节点这一组状态”的视觉对齐，不宣称整套导演台已达到 95%；最终 95% 要在后续所有已列工作台状态共同验收。

## 实现方向与验证

先为导演节点创建可测试的外层布局/状态合同，再增加独立输入与持久化，最后将关闭工作台的本地截图接入同节点封面。现有模板、场景对象、显式输出路径保持可用。测试要覆盖：旧项目兼容、输入保存和重载、无 Seedance/视频任务调用、关闭后封面、无变更不重复写入、截图失败恢复、切换项目/删除节点时阻止过期写回、键盘与鼠标交互。随后运行相关单测、类型检查，并在 BeefTV 本地复现页及真实画布做浏览器截图对比。

## 下一阶段边界

第一阶段通过后，分别设计并验收：（2）工作台整体骨架和视图切换；（3）场景树、角色、机位与属性编辑；（4）时间轴、截图、全景图和导入。涉及新 `DirectorScene` 字段时采用可迁移的加法 schema，并保留旧项目可读性。每一阶段均记录可达交互与差距，最后再做跨状态的整体视觉/行为验收。
