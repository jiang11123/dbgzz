# Canvas reusable workflows implementation plan

**Goal:** 实现画布框选封装、模板库、输入替换、后端持久运行、结果回画布的闭环。

**Architecture:** 独立 canvasworkflow 域通过窄端口调用现有任务，复用持久资源和本机安全边界。React 负责编译选择、配置模板与展示运行，不承担步骤调度。

**Spec:** ../specs/2026-10-20-canvas-reusable-workflows-design.md

**Constraints:** 原 main checkout；不清理已有改动；不提交/推送；不建立临时运行数据目录；最终用标准安装版验收。

- [x] 后端任务：实现 spec JSON 合同、模板和运行存储、映射校验、稳定任务 ID、恢复/重试/取消、资源引用保护、路由信任控制。验证领域和 HTTP 关键边界。
- [x] 前端任务：选择编译器（生成器和结果去重、来源还原、环和遗漏依赖检测）、API、封装表单、模板库与运行表单、运行进度及结果导入；最小集成到当前画布入口。验证纯函数和类型。
- [x] 集成任务：独立代码审查，修复影响实际使用的问题；更新数据库/API/功能文档；官方脚本更新安装版，验证选择、封装角色、模板库与历史来源错误提示。
- [ ] 用户实操验收：在新安装版手动跑通真实生成，保存模板、替换人物素材、运行并将结果回画布；付费生成和最终动作效果未由 Codex 执行或确认。

**Review focus:** 旧任务来源与媒体槽位映射；其他用户资源和任务；重复点击和未知提交；启动恢复与 UI 切换；生成器/结果成对选择和固定外部依赖。

**Execution:** 用户已要求直接实现。使用 subagent-driven-development 分工，产品验收/提交规则优先于技能中的自动提交或新建 worktree 步骤。

## 重进画布布局与整组删除修复

- 根因：`resetInterruptedGeneration → ensureMediaNodeMinimumSize` 对工作流卡片执行普通媒体 420px 最小尺寸和中心偏移；300×260 槽位被放大并覆盖邻居。普通背板删除只解除父子关系，工作流误用这一语义导致孤立槽位。
- 工作流槽位退出普通媒体尺寸归一化；布局版本 1 对历史实例按原有依赖列和行一次修复为 300×260，不改变 ID、资源绑定、运行回执或定义。新实例写入版本，之后重进保持已保存布局。
- 删除工作流框或控制节点按所属图级联删除内部节点及关联连线；普通背板仍只解除分组，外部参考源和其他实例保留。UI 和 Agent 使用同一删除函数；运行中工作流走确认并尝试取消运行。
- 类型检查与 26 项相关检查、166 个断言通过。安装版 v1.7.27，构建 `2026-10-20T03:10:55Z`，官方发布门禁、前端构建、媒体运行时、签名和构建标识核对通过，staging 清理。系统截图首次 -3811，经窗口重绑恢复。用户截图画布 `-NpKvUKdW9T8v6wiCfsDa` 的 3 个实例（18 节点）已恢复 300×260 槽位且上传/画布素材入口可见；实操删除中间工作流后变为 12 节点/2 组，无孤立子节点，随后撤销恢复 18 节点。回主页再进入后，截图及 API 确认槽位宽高、位置、ID、连线及绑定不变。未触发模型生成；运行中删除取消逻辑未做付费实测。旧画布此前已删除外框产生的孤立节点保持原数据，未擅自清除。未提交/推送。
