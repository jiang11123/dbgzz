# BeefAPI 模型配置与验收记录

## 验收范围

本轮使用 `fixtures/model-catalog/beefapi-20261013.json` 中的 47 个模型。它只保存模型名称和接口类型，不包含账号、凭据、请求正文或媒体链接。模型目录会变化，新增模型需要重新验证，不能用历史结果证明后续模型可用。

使用本地生产适配器调用托管 BeefAPI 接口：文本检查非空响应，图片使用合成参考图并解码结果，视频使用合成参考图并完成原任务查询和下载，语音合成检查可解码音频，语音识别使用合成语音并核对转写文字。语音识别不是生成模型，不出现在生成模型选择器中。

## 确认的适配修复

| 问题 | 修复后的行为 |
| --- | --- |
| `hy-image-v3` 的目录或旧配置将其识别为聊天模型 | 官方 BeefAPI 地址上的刷新、配置重载和执行统一使用图片协议 |
| Hy 参考图使用通用 Images edits 请求 | 使用 JSON `POST /v1/images/generations`，参考图放入 `images`，按模型合同转换尺寸，并在发送前验证限制 |
| 上游返回图片 URL，任务成功时尚未获得图片数据 | 下载并检查图片字节后返回内联结果；下载失败保留原提交记录 |
| Grok/Kling 的通用 `openai` 目录标识导致文本归类或 Sora multipart 请求 | 精确识别这两个视频模型，使用 BeefAPI 的 JSON `/v1/videos` 合同，分别传分辨率和比例 |
| Grok/Kling 参数选项超出网关支持范围 | Kling 仅提供 720p、3–15 秒和支持的比例；Grok 带图时在提交前检查 720p、最多 10 秒 |
| MP3 上传的系统 MIME 扩展名变为 `.m2a` | `audio/mpeg` 的 multipart 文件名固定使用 `.mp3` |
| Responses 插件只读取顶层 `output_text`，标准 HTTP 响应中的文本被漏掉 | 按数组顺序收集 `output[].content[].text`，分别提取推理摘要，并保留工具调用与原有顶层兼容字段 |
| 本地图片提交记录准备失败或 multipart 素材准备失败被当成提交未知 | 发送前失败明确标为尚未提交；已经存在的未知提交继续保留原任务，禁止自动重发 |
| 网关没有可用渠道被误当成用户请求过频 | 归类为模型服务不可用 |
| 视频已经返回失败状态但没有错误正文 | 保留原任务 ID，归类为异步任务失败，使用通用视频文案 |

以上协议纠正只适用于托管 BeefAPI 地址；自定义供应商保留其选择的插件和协议。

## 实测结果

47 个模型逐项调用后，44 个拿到可用结果。剩余 3 个没有通过服务可用性验收：

| 模型 | 观察到的失败 | 归因 |
| --- | --- | --- |
| `gemini-3.1-pro` | 上游 HTTP 503，暂无可用渠道 | 上游服务可用性 |
| `gemini-3.7-flash` | 上游 HTTP 503，对应分组没有可用渠道 | 上游服务可用性 |
| `grok-imagine-video-1.5` | 创建被接受，原任务随后失败；服务端记录供应商账号额度耗尽 | 上游额度；不能把创建成功当成生成成功 |

失败模型未通过验收，不自动改用别的模型，也不盲目重新提交。恢复必须查询已有任务。原始客服报告缺少服务端请求 ID，尚未能唯一关联其本地任务，因此这次修复不能证明该原任务是否提交或扣费。

## 回归证据与限制

- 前后端用同一个冻结目录验证所有模型的能力归类；旧图片、视频配置在刷新和重载后纠正。
- Hy 测试覆盖 0/1/3 张参考图、尺寸转换、两种 Base URL、旧聊天配置，以及发送前拒绝非法尺寸、参考图和参数。
- 视频测试覆盖 JSON 创建、查询、下载、恢复只发 GET、非法控制参数不创建，以及已确认失败的错误分类。
- 视频旧聊天协议在执行参数验证之前修正，防止持久任务再次被错误协议拒绝；自定义主机保持原协议。
- Responses 插件覆盖推理或工具项排在文本之前、多个文本块、工具调用和顶层兼容字段不重复拼接；Claude Opus 4.8 的实际 Responses 路径补测通过。标准结构依据 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/text)。
- 图片恢复测试保留未知结果不重发、同一提交记录重启恢复、并发归属和下载失败不变成新付费请求的保护。
- 前端专项测试和类型检查通过，后端相关包测试与构建通过。较早的相关包全量回归通过；后续 `app` 全包复跑达到默认 10 分钟总时限，未报告单项断言失败，改用此次影响的图片提交、恢复和视频恢复专项测试，全部通过。
- 真实媒体检查覆盖 5 张可解码图片、9 个可解码视频、3 个可解码音频，以及识别为“你好，这是模型接口测试。”的语音。
- 本轮是本地代码与模型接口验收，尚未证明 Windows 安装包、原报告电脑上的生成和画布绑定、或发布后的运行状态。修复尚未合并或发布。

## 付费复验

`backend/internal/generation/model_adapter_live_test.go` 默认跳过，必须显式开启付费测试、指定已有测试连接、账务查询执行器、输出目录和预算。它在提交前保存测试身份并查询实际账务，默认不重复已有记录；未知结果保留预算预留。缓存恢复和视频原任务查询需要显式选择已有身份。

不得使用用户未确认的原任务做重新生成测试。后续复验仅测试新建的合成素材任务，或查询已经创建的任务；预算与服务端渠道变更需有对应授权。
